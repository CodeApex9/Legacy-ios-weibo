## 0. 一句话概述

这是一个**不依赖 Xcode、不依赖 Theos**的 iOS 5–7 原生 App：用命令行 clang 交叉编译 armv7，用 `ld64` 手工链接（跳过 `crt1.o`、自造 `LC_UNIXTHREAD` 入口），用 `ldid` 做 ad-hoc 签名，通过 SSH/scp 装进越狱 iPhone 5 并 `respring` 生效。全部贴图由 Python 脚本逐像素预渲染，仓库里没有任何美术源文件。

业务上是一个微博客户端：热门 / 关注 / 我的 三流列表、微博正文 + 热度序评论区、账号详情面板与扫码登录、退出登录。

## 3. 技术路线

### 3.1 为什么不用 Xcode / Theos

| 路线 | 卡点 |
|---|---|
| Xcode | 新版 Xcode 已不支持 armv7 + iOS 5/6 部署目标；且工程需要 `.xcodeproj` 与 storyboard，对 320×480 的老界面是负担 |
| Theos | 依赖 `iPhoneOS*.sdk` 与 `ldid`，本机没有可用老 SDK；且 Theos 默认链接 `crt1.o`，与新 ld64 冲突 |
| **本方案** | clang + ld64 + 自制 mini SDK：**零 Xcode、完全离线可编**，一次 `make` 约 3 秒 |

### 3.2 三段式工具链

```
                    ┌──────────────────────────────┐
  src/*.m  ────────▶│ clang -target armv7-apple-    │──▶ build/*.o
  include/mini/*.h  │  ios5.0 -isysroot mini-sdk    │
                    │  -fobjc-runtime=ios-5.0       │
                    │  -fno-objc-arc -O2            │
                    └──────────────────────────────┘
                                  │
                    ┌─────────────▼────────────────┐
                    │ ld -arch armv7               │──▶ LegacyApp（Mach-O arm_v7）
                    │  -platform_version ios 5 9.3 │    LC_VERSION_MIN_IPHONEOS 5.0
                    │  -e _main -no_pie            │    单段 LC_UNIXTHREAD
                    │  -L mini-sdk/usr/lib         │
                    │  -F mini-sdk/…/Frameworks    │
                    └──────────────────────────────┘
                                  │
                    ┌─────────────▼────────────────┐
                    │ ldid -S（ad-hoc 伪签名）      │──▶ 装机（AppSync 放行）
                    └──────────────────────────────┘
```

关键参数（`Makefile`）：

```make
CFLAGS  := -target armv7-apple-ios5.0 -arch armv7 -isysroot ../toolchain/mini-sdk \
           -miphoneos-version-min=5.0 -fobjc-runtime=ios-5.0 \
           -fno-objc-arc -fno-modules -O2 -Iinclude/mini
LDOPTS  := -arch armv7 -platform_version ios 5.0 9.3 -e _main -no_pie
LDLIBS  := -framework Foundation -framework UIKit \
           -framework CoreGraphics -framework CoreFoundation -lobjc -lSystem
```

三个决定必须保留：

1. **不链 `crt1.o`**。iOS 9.3 SDK 里那份是老式 ARM 汇编，ld64 27106 已不支持它的 `SECTDIFF` 重定位会直接报错。入口改由 `-e _main` + `LC_UNIXTHREAD` 指定，`main.m` 里手工补齐 C 运行时全局（`__CFConstantString` 等）。
2. **`-no_pie`**。老 dyld 对 `PIE + LC_UNIXTHREAD` 的 slide 处理不一致，关掉更稳；越狱分发不要求 PIE。
3. **只链 mini stub**。完整 SDK 的 patched tbd 里混入了 i386/x86_64 切片，新版 ld64 会误判为 iOS-simulator 目标而报错。

### 3.3 mini SDK 是什么（这条决定了很多"能不能做"）

`../toolchain/mini-sdk` 里没有二进制库，只有 **6 个 `.tbd` 文本桩 + 一层头文件**：

```
mini-sdk/
├── SDKSettings.plist
├── System/Library/Frameworks/
│   ├── UIKit.framework/UIKit.tbd
│   ├── Foundation.framework/Foundation.tbd
│   ├── CoreGraphics.framework/CoreGraphics.tbd
│   └── CoreFoundation.framework/CoreFoundation.tbd
└── usr/lib/{libobjc.tbd, libSystem.tbd}
```

由此得到两条硬规则：

| 符号类型 | 是否需要在 tbd 登记 | 原因 |
|---|---|---|
| **Objective-C 方法**（`-setBackgroundImage:forState:` 等） | **不需要** | 走 `objc_msgSend` 运行时派发，链接期只依赖类符号（`OBJC_CLASS_$_UIImage`），类已登记即可 |
| **C 函数**（`strncat`、`unlink`、`UIGraphicsBeginImageContextWithOptions`…） | **必须登记** | 链接期按名绑定，缺一个就 `Undefined symbols` |

所以本项目的做法是：头文件里补声明（编译期可见），tbd 里按需补 C 符号（链接期通过）。真机上这些符号由系统真库提供，一定存在——**但补 tbd 前要确认系统确实有该 API**（例如 `unlink` 没登记，我们改用 `open(O_TRUNC)` 把凭据文件截断为 0 字节，绕开这个不确定性）。

### 3.4 启动链

```
内核 → LC_UNIXTHREAD(pc = _main) → main()  [src/main.m]
   ├─ 手工初始化 C 运行时所需全局（没链 crt1.o）
   └─ UIApplicationMain(...) → AppDelegate → RootViewController
```

### 3.5 一条必须遵守的编码约束：不要给自定义类加实例变量

二进制跳过了 `crt1.o` 手工链接，non-fragile ObjC2 ABI 的 `_OBJC_IVAR_$` 偏移变量在 iOS 5/6 的 libobjc 上可能未初始化——ivar 会读到对象起始处的 `isa`（非零）而不是 `nil`，历史上导致过"window 被判定为已创建"从而跳过创建、**界面全黑**。

因此：**所有界面状态用 C 静态变量保存**（`src/AppDelegate.m` 顶部有详细注释），`@interface` 里只有方法，没有 ivar。这条是硬约束，新增代码必须遵守。

### 3.6 贴图全部由脚本预渲染

`scripts/make_assets.py`（21 KB，零第三方依赖）用 `struct + zlib` 手写 PNG 编码，逐像素生成 **35 张 PNG**：

- 皮革噪点导航条（确定性 value noise + 双线性插值）
- 深蓝凹槽 / 亮蓝浮块（玻璃高光）
- 亚麻底平铺贴图（8pt 循环）
- 纸卡九宫格底图、可平铺缝线
- 立体胶囊按钮（深蓝 / 红 × 常态 / 按下）
- 图标、启动图、占位图

好处：改颜色只改常量（`NAV_STOPS` / `LINEN` / `BTN_NAVY`…），不需要美术资源，也不会出现"找不到切图"的问题。

### 3.7 自检体系（在没有截图工具的设备上做视觉验证）

设备上没有 `screencapture`，也没有可用 `libimobiledevice`，所以视觉回归靠 **app 内离屏渲染**：

```objc
UIGraphicsBeginImageContextWithOptions(size, NO, 0.0f);
[(LegacyLayerShim *)[[self view] layer] renderInContext:UIGraphicsGetCurrentContext()];
UIImagePNGRepresentation(img) → /tmp/legacy_shot.png
```

再用 `scp` 拉回主机看。所有验证开关都只在 `DIAG=1` 时编译，正式版二进制里**一个字符串都不留**（每次出包都用 `strings | grep` 复核）。

### 3.8 装机流程

```
make ipa  →  build/LegacyApp.ipa
scripts/install.sh [respring|launch|usb]
   ├─ ssh 连通性探测（放宽 ssh-rsa / group1 / CBC，适配 OpenSSH 6.7）
   ├─ scp .app → /Applications/LegacyApp.app
   ├─ chmod 755 + killall（若有旧进程）
   └─ respring（可选）
```

## 6. 接口备忘（m.weibo.cn 非公开接口）

**分组时间线（逆向 weibo-lite main 分包确认，2026-11-17 真机实测）**：
- `GET /api/config/list` → `data.groups[]`：服务端分组列表（特别关注/美图/壁纸等自定义分组），每项含 `gid`
- `GET /feed/group?gid=<gid>[&max_id=...]` → `data.statuses[]`，字段与 `/feed/friends` 同款，`data.max_id` 翻页
- 手机版网页无 UI 暴露分组流（懒加载分包里才有），需从 JS 分包 `h5.sinaimg.cn/m/weibo-lite/js/main.*.js` 逆向定位
- App 侧：`WeiboStoreFetchGroups` 拉分组列表（独立连接，不占用 feed 通道），回调 `WeiboStoreSetGroupsCallback`；拉取时顺带缓存「特别关注」的 gid，feed 3 两段式的第一段从此可省

| 用途 | 请求 | 分页 | 备注 |
|---|---|---|---|
| 热门 | `/api/container/getIndex?containerid=102803&since_id=` | `since_id` | 解析 `cards[].mblog` |
| 关注 | `/feed/friends` | `max_id`（`data.max_id_str`） | 解析 `data.statuses` |
| 我的 | `/api/container/getIndex?containerid=107603<uid>&page=` | `page` | — |
| 评论 | `/comments/hotflow?id=<id>&mid=<id>&max_id_type=0[&max_id=]` | `max_id` + `max_id_type` | **id 与 mid 都必须带**，只带 id 返回 `ok:0` |

必须知道的三件事：

1. **`id` / `max_id` 的类型不稳定**（有时字符串、有时数字）。取值必须兼容两种，且**不要用 `intValue`**——微博 id 是 64 位时间戳，会截断。
2. **`total_number` 包含已删除评论**（实测某条显示 25、实际只能拉到 15）。没有下一页时按真实条数显示。
3. **老接口 `/comments/show` 已失效**，只能用 `hotflow`。

## 8. 踩过的坑与解法（复用时最该先读这一节）

| 现象 | 根因 | 解法 |
|---|---|---|
| 启动后**全黑** | 自定义类加了 ivar，`_OBJC_IVAR_$` 偏移未初始化，读到 `isa` 而非 nil | 状态全部改为 C 静态变量，类里不加 ivar |
| 链接报 `SECTDIFF` 重定位错误 | iOS 9.3 SDK 的 `crt1.o` 是老 ARM 汇编 | 不链 `crt1.o`，`-e _main` + `LC_UNIXTHREAD`，main.m 手工补运行时 |
| ld64 把目标误判为 iOS-simulator | 完整 SDK 的 patched tbd 混入 i386/x86_64 切片 | 只用 mini stub（纯 armv7 tbd） |
| `Undefined symbols: _strncat / _unlink` | 这两个 C 符号未在 `libSystem.tbd` 登记 | 手工拼字符串避 `strncat`；用 `open(O_TRUNC)` 截断代替 `unlink` |
| tab 选中块右端像直角、右缝被吃掉 | `UISegmentedControl` 内部拉伸/裁剪分段背景图，几何不可控 | 放弃背景图方案，改独立视图（槽 + 浮块）自绘 |
| tab 文字里出现**绿色竖线** | 该控件自绘的分隔线/bevel，被系统 tint 染色，正好落在段中心 | **彻底自绘**：删掉控件，改 3 个 UILabel + 3 个透明 UIButton |
| 卡片缝线被拉成不等距长条 | 缝线烘进了九宫格底图，中间段拉伸导致虚线变形 | 拆成 1pt 可平铺贴图，`colorWithPatternImage` 运行时铺 |
| 退出登录后重启又变回已登录 | bundle 内 `Login.txt` 是只读的（root 属主），删不掉 | 写 `<HOME>/weibo_logout.flag` 标记，`InitLogin` 见到就跳过凭据；重新扫码时清除 |
| 关注流上拉全是重复数据 | ①翻页条件要求 `sPage>1`，但关注流从不递增；②`data.max_id` 是数字，代码按字符串判断 | 改为"有游标就带 max_id"；兼容数字/字符串并优先 `max_id_str`；追加时按 id 去重 |
| 评论数"共 25 条"却只列 15 条 | 接口 `total_number` 含已删除评论 | 无下一页时按实际条数显示 |
| 分组表格背景还是灰蓝条纹 | 只设 `backgroundColor`，系统仍绘自己的底 | 同时设 `backgroundView` |
| 圆角按钮按下闪一块蓝 | `kButtonTypeRounded` 的默认高亮底 | 给 normal/highlighted/selected 都铺透明背景图 |
| 自检截图里按钮位置判断错 | `hitTest:` 的点是**自身坐标系**，我传了屏幕坐标 | 用 `[view bounds]` 相对坐标 |
| 设备上看不到界面效果 | 无 `screencapture`、无 libimobiledevice | app 内 `renderInContext` 离屏渲染写 PNG，再 scp 拉回 |
| 先 `make DIAG=1` 再 `make` 报 `Undefined symbols: _LegacyNetProbe` | `.o` 只依赖头文件时间戳，编译开关变化不触发重编，DIAG 的旧目标文件被拿去链接非 DIAG 目标 | Makefile 里加编译开关指纹 `build/.cflags`，CFLAGS 变化即全量重编 |
| 指纹升级后仍混链：`clean -> make -> make DIAG=1` 同一秒内跑完，`.cflags` 与 `.o` mtime 同秒，make 误判 `.o` 最新，DIAG 版二进制里混进 release 的 `RootViewController.o`（自检全静默、日志只有 setupWindow 8 行） | mtime 秒级精度 + 指纹靠 mtime 触发重编的机制缺陷 | 指纹改为**构建期规则**：`$(BUILD)/.cflags: FORCE`，内容变化时直接 `find build -name '*.o' -delete` 再全量重编；不能用 parse 期 `$(shell)`（make 3.81 下 DIAG 构建后 `make clean` 会报 missing separator） |
| 36pt 高的新按钮出现**双下巴**（一整颗胶囊下又露出一截） | `resizableImageWithCapInsets:` 上下 inset 为 0 时中间带**按原尺寸平铺**而非拉伸；老按钮一直没炸只因底图恰好等于按钮尺寸，新按钮（BtnNavy 26pt 图撑 36pt）立刻触发 | 高按钮用同高底图：`make_assets.py` 新增 `BtnBlue36`（92x36，BtnNavy 同配色）；见技能包 pitfalls 同条 |

## 10. 已知限制与风险

| 类别 | 说明 |
|---|---|
| 架构 | 仅 armv7，不支持 arm64（iPhone 5s 以上跑 iOS 11+ 的设备无法使用） |
| 语言特性 | 无 ARC、无 Auto Layout、无 Storyboard；QuartzCore 未链接，layer 能力通过 `LegacyLayerShim` 声明后运行时调用 |
| 接口 | 全部依赖 m.weibo.cn 非公开接口，字段/类型随时可能变化；变更时需按第 6 节重新实测 |
| 凭据 | 凭据以明文存放在 bundle 内只读 `Login.txt` 与 `/var/mobile/weibo_login.txt`；仅适用于个人越狱设备 |
| 权限 | bundle 内 `Login.txt` 属主是 root，`mobile` 用户无法改写，退出登录只能靠标记屏蔽而非删除 |
| 内容 | 表情显示为文字（如 `[doge]`），未渲染表情图；不支持发博、点赞、转发、私信、推送 |
| 评论翻页 | 详情页未给 scrollView 设 delegate（避免串到主列表的上拉加载），翻页靠底部按钮 |
| 自检 | 所有视觉验证依赖手工加编译开关出包，不是自动化 CI |

## 11. 能否固化成技能包

**结论：可以，而且是高价值的一次性投入——但要分清哪部分能固化、哪部分不能。**

### 11.1 可固化的三层

| 层 | 内容 | 固化形式 | 复用价值 |
|---|---|---|---|
| **L1 工具链与构建**（100% 可固化） | clang 参数、`crt1.o` 绕过、`LC_UNIXTHREAD`、mini SDK 结构、ldid 签名、install.sh、自检开关 | `scripts/` + `references/toolchain.md` | 极高：这套"坑"重踩一次要几小时到几天 |
| **L2 骨架工程**（可参数化） | 无 ivar 约定、C 静态变量模式、单一回调数据层、cell 复用、自绘下拉刷新、图片缓存、离屏截图自检 | 可生成的模板工程 | 高：新 app 直接得到能跑的空壳 |
| **L3 视觉体系**（可固化） | 拟物三材质 + 四条光照规则 + `make_assets.py` 全套生成器 + 九宫格/平铺贴图套路 | `assets/` + `make_assets.py` 模板 | 高：换个主色即可复用到同类复古 app |
| L4 业务（不可固化） | 微博接口语义、字段类型怪癖、页面信息架构 | 只写进 `references/api-notes.md` 作提示 | 低：每个 app 都不同 |

### 11.2 建议的技能包结构

```
legacy-ios-shell/
├── SKILL.md                     # 触发词与工作流（何时用、怎么生成、怎么验证）
├── references/
│   ├── toolchain.md             # 交叉编译三段式、mini SDK 契约、必须保留的编译参数
│   ├── mini-sdk-symbols.md      # ObjC 方法 vs C 函数的符号规则；已登记符号清单
│   ├── pitfalls.md              # 第 8 节全部坑（含现象→根因→解法）
│   ├── ui-v03.md                # 三材质 / 四光照 / Token 表 / 组件规格
│   └── selfcheck.md             # 自检开关矩阵与离屏截图做法
├── scripts/
│   ├── make_assets.py           # 参数化：主色、圆角、材质开关
│   ├── install.sh               # 已含老 OpenSSH 兼容参数
│   └── new_app.py               # 生成骨架（bundle id / 显示名 / 主色）
└── assets/
    └── skeleton/                # Makefile、Info.plist、main.m、AppDelegate.m、LegacyKit.h 起点
```

### 11.3 技能能自动化到什么程度

| 步骤 | 能否自动 |
|---|---|
| 生成可编译空壳 + 跑通 `make ipa` | ✅ 能 |
| 生成拟物皮肤（换主色） | ✅ 能 |
| 装机 + respring + 拉日志 | ✅ 能（设备 IP / 密码做参数） |
| 离屏截图对比"改前/改后" | ✅ 能（自检开关已具备） |
| 判断某接口字段是不是数字/字符串 | ❌ 不能，必须实测（本项目两次栽在这上面） |
| 决定"这里该用哪种交互" | ❌ 不能，需人定 |

### 11.4 落地建议

先只固化 **L1 + L3**（工具链 + 视觉体系），做成 `legacy-ios-shell`：新项目一条指令拿到"能编译、能装机、界面有 V0.3 皮肤"的骨架，再按业务往 `RootViewController` 里填。**不建议把微博业务一起塞进技能包**——接口一旦变化，技能里的示例代码会误导后来者，反而增加维护成本。

如果你确认要做，我可以按上面的结构生成整套技能包，并用一个空白骨架工程实跑一遍 `make ipa` + 装机验证，确保技能里的脚本不是"写完没跑过"。
